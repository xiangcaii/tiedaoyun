# 工作空间启动台设计

## 目标

把登录后的工作空间页从默认的后台卡片列表，升级为清晰、可识别的业务应用入口。用户应在首屏快速完成三件事：识别自己可进入的工作空间、筛选目标工作空间、创建新的工作空间。

本设计面向 PC 端，遵循 `docs/staging/specs/2026-08-04-web-ui-design-spec.md`：使用 Ant Design 5、现有系统字体和蓝色主题 Token，保持 1280px 最小宽度及四态完整性。

## 范围

### 包含

- 优化工作空间列表页的页面层级、筛选工具栏、工作空间卡片、空态和创建入口。
- 将创建工作空间从 Modal 改为右侧 Drawer，保留现有表单字段、校验和 API 调用。
- 优化工作空间设置页的对象头部、分区导航和危险操作区，使其与列表页形成同一产品体验。
- 抽取局部 CSS，使视觉值不再散落在 JSX 行内样式中。
- 保持现有路由、React Query、权限判断、删除确认与 i18n key 的业务行为不变。

### 不包含

- 不增加概览统计、最近活动、应用列表或成员管理；当前没有可靠数据源支撑这些内容。
- 不修改后端接口、数据模型、权限模型或工作空间状态语义。
- 不引入字体、图片资产、新 UI 库、深色主题或品牌渐变。

## 设计方向：工作空间启动台

工作空间不是一条普通记录，而是进入一组业务应用与搭建能力的边界。视觉签名为每张卡片左侧的“身份轨道”：由工作空间 Logo/首字母和主色系构成的一条细色带，帮助用户在不增加装饰噪声的情况下快速扫读不同入口。

页面整体保持克制：白色内容容器置于 `colorBgLayout` 背景上，圆角使用 8px，主要信息依赖排版、留白和边框分层，不使用重阴影或无意义动画。

### Token

| 语义       | 值/来源                                | 用途                                                     |
| ---------- | -------------------------------------- | -------------------------------------------------------- |
| 品牌与焦点 | `colorPrimary` / `--tdy-color-primary` | 创建按钮、身份轨道、进入箭头、当前导航。                 |
| 页面背景   | `colorBgLayout`                        | 页面最外层背景。                                         |
| 内容容器   | `colorBgContainer`                     | 工具栏、卡片、设置区块。                                 |
| 元信息     | `colorTextSecondary`                   | slug、创建时间和辅助说明。                               |
| 危险操作   | `colorError`                           | 删除区标题、边框与确认按钮。                             |
| 间距       | 8px 网格                               | 页面 24px；区域 24px；卡片/工具栏 16px；紧凑元信息 8px。 |

系统字体栈继续承担标题、正文和数据文本；不引入第二字体，以保证后台与后续设计器的可用性与一致性。

## 页面设计

### 工作空间列表 `/workspace`

```text
┌──────────────────────────────────────────────────────────────┐
│ 工作空间                                  [＋ 新建工作空间]   │
│ 选择一个空间，进入团队的应用、数据与自动化。                  │
├──────────────────────────────────────────────────────────────┤
│ [搜索名称或 slug________________] [状态] [排序]              │
├──────────────────────────────────────────────────────────────┤
│ ┌────┬──────────────────────┐  ┌────┬──────────────────────┐ │
│ │ ██ │ 人事中心       [正常] │  │ ██ │ 运营协作       [归档] │ │
│ │ ██ │ hr-center              │  │ ██ │ ops-hub               │ │
│ │    │ 创建于 …               │  │    │ 已归档，不可进入       │ │
│ │    │ 进入工作空间 →      ⋯ │  │    │ 查看设置            ⋯ │ │
│ └────┴──────────────────────┘  └────┴──────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

- 页面头不再套入 Card。标题为 24px，说明只描述用户可做的动作；“新建工作空间”是页面唯一 Primary Button。
- 搜索、状态和排序位于同一条工具栏。搜索框占据视觉起点，筛选与排序为次要控制项；小屏幕不在本期范围内。
- 卡片采用三列 Grid。卡片主区域可进入设置，更多菜单是独立可操作区域，避免事件冒泡造成误跳转。
- 卡片只展示一次 slug；元信息显示创建时间。正常状态使用语义 Tag，归档状态显示中性 Tag 和“已归档，不可进入”的明确文案。
- “进入工作空间”使用带右箭头的文字型操作，视觉上由身份轨道与名称承接，不重复制造第二个主按钮。
- 空态包含原因说明和“创建第一个工作空间”操作；加载态仍渲染同尺寸的三列骨架；错误态保持头部与工具栏，错误区只替换列表区域。
- 创建使用右侧 Drawer，宽度约 440px。Drawer 标题、字段、校验及提交状态复用现有 `WorkspaceCreateForm` 与 mutation。

### 工作空间设置 `/workspace/:id/settings`

- 顶部新增对象头：返回工作空间、Logo/首字母、名称、slug、状态。它既确认当前上下文，也避免在内容区重复裸标题。
- 保留左侧三项锚点导航（基础信息、外观设置、危险操作），但以“工作空间设置”作为导航标题，当前分区使用主色指示。
- 内容区限制为舒适的编辑宽度，基础信息和外观各自为一个分区 Card；字段标签上置，保存按钮放在分区末尾。
- 危险操作放在页面最后，使用浅错误色边界与影响说明；仅 owner 显示删除按钮，非 owner 只显示只读说明。
- 加载、错误、工作空间不存在和只读状态沿用当前逻辑，但使用与列表页一致的页面内边距和容器层级。

## 组件与实现边界

| 单元                              | 职责                                                         | 依赖                                    |
| --------------------------------- | ------------------------------------------------------------ | --------------------------------------- |
| `WorkspaceListPage`               | 管理查询状态、页面头、工具栏、Grid、Drawer 和现有 mutation。 | 现有 workspace API、auth store、i18n。  |
| `WorkspaceLaunchCard`（局部组件） | 仅渲染一个工作空间入口的身份、状态、元信息和操作。           | `WorkspaceItem`、AntD、图标。           |
| `WorkspaceCreateForm`             | 保持字段与校验职责不变，仅由 Drawer 承载。                   | AntD Form、i18n。                       |
| `WorkspaceSettingsPage`           | 管理对象头、导航与三个设置分区；保留现有请求与权限判断。     | 现有 workspace API、auth store、i18n。  |
| 页面 CSS                          | 保存启动台和设置页的局部 BEM 样式，引用语义 Token。          | `theme.ts` 中的 CSS 变量与 AntD Token。 |

不将页面特有卡片提升至 `packages/ui-kit`，因为它包含工作空间业务语义；只有未来多个模块复用同一“入口卡片”模式时才考虑抽取。

## 数据、错误与权限

- 查询参数、分页、创建、更新和删除请求均不变；视觉改造不改变 API 契约。
- 创建成功后继续关闭容器、刷新列表并跳转设置页；slug 冲突仍映射为字段错误，不清空用户输入。
- 删除继续要求输入工作空间名称并由服务端判定 owner 权限；列表更多菜单与设置页危险操作的可见性仅为前端辅助。
- 已归档工作空间仍可见但不可进入；更多菜单保留可用的设置查看路径，不能伪装为可启动入口。

## 验收与测试

- 页面头、工具栏、列表、分页和四态在改造后均可访问且不改变业务行为。
- 正常与归档卡片在视觉与交互上可区分；归档卡片不可进入。
- 创建入口以 Drawer 呈现，字段校验、提交 loading、成功跳转与 slug 冲突处理保持有效。
- owner 与非 owner 在设置页分别得到可编辑和只读体验；删除仍要求名称确认。
- 增加或更新前端测试，覆盖 Drawer 打开/提交、入口卡片的归档禁用以及设置页对象头的关键状态。
- `make lint && make typecheck && make test` 通过。

## 实施顺序

1. 扩展主题的必要语义变量并新增页面局部 CSS。
2. 改造列表页为启动台结构，抽取局部入口卡片并将创建容器切换为 Drawer。
3. 改造设置页对象头、分区容器与危险操作视觉。
4. 更新测试，执行 lint、typecheck 与 test。
